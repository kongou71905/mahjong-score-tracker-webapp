## 1. テスト方針・実施フェーズ

実装品質と実運用（iPad mini 6 Safari ＋ Google スプレッドシート連携）の両面を確実に検証するため、以下の4段階でテストを実施する。
すべてのテストケースは **正常系**（仕様どおりの操作で期待どおり動作すること）と **異常系**（不正入力・境界外・通信エラー・禁止操作に対して適切にブロック／エラー表示／復旧すること）に分けて検証する。

| フェーズ | 対象・目的 | 実施環境 |
| :--- | :--- | :--- |
| **Phase 1：ロジック単体テスト** | 麻雀スコア計算（ウマ・オカ・端数切り上げ・ゼロサム・飛び・焼き鳥）、入力バリデーション、ルール補完ロジックの正確性検証 | 自動テストまたは確認データ入力 |
| **Phase 2：機能・状態遷移テスト** | 全画面の遷移、未確定データ途中保存・自動復帰、過去データ閲覧・編集・削除の一連フロー検証 | PCブラウザ（ブラウザ保存モード） |
| **Phase 3：GAS・シート結合テスト** | GAS Web API 通信、スプレッドシート読み書き、重複送信ガード、日付タイムゾーンずれ防止の確認 | 開発環境 ＋ 実 Google スプレッドシート / GAS |
| **Phase 4：実機・UI/UXテスト** | iPad mini 6 Safari での表示崩れ・ピンチ縮小・テンキー操作性・ホーム画面追加（ITP対策）の検証 | iPad mini 6（Safari・縦向き／横向き） |

## 4. 付録：ブラウザの `localStorage` の確認・削除方法

テスト（特に `A-05`・`A-06`・`D-01`・`D-05`・`D-08` 等）で `localStorage` の中身を確認したり初期化したりする場合は、以下の手順で行います。

### 4.1 本アプリが保存する主なキー一覧

| キー名 | 内容 |
| :--- | :--- |
| `mj_storage_mode` | 接続モード（`gas` または `local`） |
| `mj_gas_url` | 保存済みの GAS WebアプリURL |
| `mj_draft_new` | 新規対局中の未確定データ（ルールスナップショット・入力済み試合・チップ） |
| `mj_local_db` | 「ブラウザ保存モード」で保存した全データ（対局者・成績・詳細・ルール設定） |

---

### 4.2 PCブラウザで確認・削除する方法（Chrome / Edge）

1. アプリを開いた状態で **開発者ツール** を開く。
   - Windows：`F12` キー または `Ctrl + Shift + I`
   - Mac：`Cmd + Option + I`
2. 上部タブの **「Application（アプリケーション）」** をクリックする（表示されていない場合は `>>` ボタンから選択）。
3. 左側メニューの **「Storage（ストレージ）」＞「Local storage（ローカルストレージ）」** を展開し、表示されたアプリのURLをクリックする。
4. **内容の確認**：
   - 右側の一覧にキーと値が表示される。行をクリックすると、画面下部のプレビュー欄に展開された中身（JSON）が表示される。
5. **削除の方法**：
   - **特定のキーだけ削除する場合**：消したい行（例：`mj_draft_new`）を右クリック ＞ **「Delete（削除）」**（または行を選択して `Delete` / `Backspace` キー）。
   - **すべてのキーを一括削除する場合**：左側のアプリURLを右クリック ＞ **「Clear（消去）」**（または右側上部の斜線入り丸アイコン「Clear all」）。
6. 削除後、動作を確認するため **ページを再読み込み（リロード）** する。

> ※ **Mac Safari** の場合は、事前に「Safari」＞「設定」＞「詳細」＞「Webデベロッパ用の機能を表示」をONにした上で、`Cmd + Option + I` で Webインスペクタを開き、**「ストレージ」タブ ＞「ローカルストレージ」** から同様に確認・削除できます。

## 5. 付録：E-03（二重送信ガード）の具体的なテスト手順

アプリの通常画面では二重クリック防止や保存完了後のデータ消去が働くため、意図的に同じ `session_id` を2回送信するテストは、以下の手順で再現します。

### 5.1 アプリ画面＋`localStorage` で再現する手順（コード不要・推奨）

1. **テスト用の対局を入力する**
   - GAS連携モードで新規対局を開始し、1戦だけ入力する（※この時点ではまだ「終了」を押さない）。
2. **送信前の `mj_draft_new` を控える**
   - 開発者ツール（`F12` ＞「Application」＞「Local storage」）を開き、`mj_draft_new` の値（JSON文字列）をコピーしてメモ帳等へ控えておく（この中に `session_id` が含まれる）。
3. **1回目の保存を実行する**
   - アプリ画面へ戻り、「終了」＞「保存して終了」を押して1回目の保存を完了させる（`mj_draft_new` は自動消去される）。
4. **同じ `session_id` の未確定状態を復元する**
   - 開発者ツールの「Local storage」で一覧の空白行をダブルクリックし、キー名に `mj_draft_new`、値に手順2で控えたJSON文字列を貼り付けて Enter を押す。
   - ブラウザを再読み込みし、1回目と同じ `session_id` のまま成績表示ビューへ自動復帰させる。
5. **2回目の保存を実行する**
   - もう一度「終了」＞「保存して終了」を押す。
6. **結果を確認する**
   - Google スプレッドシートの `DailyRecords` / `GameDetails` を開き、該当 `session_id` の行が **1回分しか保存されていない（重複追記されていない）** ことを確認する。
   - （必要に応じて開発者ツールの「Network」タブで `exec` 通信の Response を確認し、1回目が `"skipped": false`、2回目が `"skipped": true` になっていることも確認できる）
7. **後片付け**
   - 確認完了後、アプリ上の「過去データ」からテスト用対局を開き、「編集」＞「削除」でシートからテストデータを削除する。

### 5.2 （補足）同時送信による排他制御まで厳密に確認する場合

開発者ツールの「Console」タブで GAS の `/exec` URL 宛てに同一 `session_id` の `saveSession` リクエストを `Promise.all` で同時に2回送信すると、`LockService` による排他制御下で1つ目のみ保存・2つ目が `skipped: true` としてスキップされる動作まで確認できます。
